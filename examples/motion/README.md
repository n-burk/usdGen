# Motion examples

All seven scenes run for **100 frames at 24 fps**. Select `/World/Camera`, enable
scene materials and scene lights, and use Storm at Very High complexity. The
grooms are generated by native usdGen operators on the CPU reference lane.

| Scene | Animation and hierarchy |
|---|---|
| [felt_sphere_animated.usda](felt_sphere_animated.usda) | Sphere point deformation supplies two volume-preserving squash/stretch cycles. `/World/Motion` moves left/right. The groom is inside that Xform. |
| [felt_sphere_groom_outside_xform.usda](felt_sphere_groom_outside_xform.usda) | Identical sphere animation, but the groom is at `/World/Groom`. Surface RBF carries both deformation and relative Xform motion into the groom's space. |
| [braid_animated_guides.usda](braid_animated_guides.usda) | Three animated input guide curves bend a three-bundle braid on a stationary sphere. Fixed roots and guide interpolation generate the braid, without Scatter. |
| [braid_animated_guides_and_surface.usda](braid_animated_guides_and_surface.usda) | The same guide animation plus sphere squash/stretch and parent translation. Guide RBF is followed by surface RBF. |
| [braid_simulated_center_curve.usda](braid_simulated_center_curve.usda) | One simulated center curve carries a hanging braid using native curve-wrap deformation. Only the centerline is baked; growth remains live. |
| [two_curves_ptex_regions.usda](two_curves_ptex_regions.usda) | Two strands in one description, each grown and animated within its Ptex region by one of two center curves. |
| [two_braids_ptex_regions.usda](two_braids_ptex_regions.usda) | Two braids of 381 fibers each in one description, with Ptex-separated growth and center-curve deformation. |

From the pipeline repository:

```powershell
.\tools\launch_usdview.ps1 <usdgen-src>/examples/motion/felt_sphere_groom_outside_xform.usda
```

Restart an existing viewer to load the rebuilt usdGen DLLs. The static Ptex felt
study remains at `../felt/felt_sphere.usda`; these motion studies use simpler
materials and grooms to make deformation easier to inspect. Studio illumination
uses fixed key, fill and back RectLights under `/World/Studio` in the two felt
sphere scenes, plus the contrasting `../felt/textures/studio_contrast.exr` HDR.
The braid studies retain their environment illumination from
`../felt/textures/studio.exr`. The felt rig is shared with the static sphere;
see [its lighting notes](../felt/README.md#three-point-studio) for Storm and
Moonray settings. Select `/World/Camera` in the motion scenes.

## Rest generation and downstream motion

Sphere chain:

`Scatter → Grow → Curl → Width → surfaceAnimate (UsdGenDeform)`

Scatter evaluates Default-time Catmull–Clark limit geometry at isolation level 3.
The 3,188 strands / 25,504 CVs are generated and styled once. Surface RBF uses 64
rest mesh vertices and `lockRoots=false`. Its input is in **surface rest-local
coordinates**; its output is in **current groom-local coordinates**. Shared
ancestor transforms cancel inside the operator and are applied by publication.
If the groom is outside the moving hierarchy, the operator includes the relative
motion instead. Do not apply the surface transform to the input groom as well.

Braid chain:

`CurveSource → GuideInterpolate → Width → guideAnimate (UsdGenDeform)`

The combined scene appends `surfaceAnimate (UsdGenDeform)`.

`/World/Motion/RestInputs` contains three Default-time braid guides and 381 short
root seed curves in a fixed concentric layout. CurveSource binds these roots to
the rest surface once; GuideInterpolate grows 64 CVs per strand (24,384 total).
There is no Scatter operator. Only these sparse guides and short root seeds are
authored: the full braid is generated live. The growth guides stay static.

`/World/Motion/Drivers` contains the animated input curves with a separate rest
snapshot. Guide RBF samples 128 CVs and uses `lockRoots=true`, so the tips sway
while the roots remain attached. In the combined scene these drivers describe
**local residual bending**, before skin deformation. Surface RBF then applies
the skin's squash/stretch to the bent braid. The moving parent is applied once.
Drivers that already include skin/world motion would need that motion removed
before feeding this two-deformer setup. Enable Display > Guide to inspect inputs.

The CPU surface RBF extension exactly reproduces affine squash/stretch. For
arbitrary nonlinear skin motion it is an approximation, not an exact barycentric
or limit-surface wrap. These examples do not add a new SurfaceAnimate schema;
`surfaceAnimate` is the name of a `UsdGenDeform` node.

## Regeneration and validation

### Single simulated center curve

`braid_simulated_center_curve.usda` hangs the braid from the sphere. Its only
animated curve is `/World/Motion/SimulatedCenter`: 31 particles, the first three
pinned, simulated with Verlet integration, gravity, changing wind, damping and
PBD segment-length constraints. Eight substeps and 80 constraint sweeps per
substep produce 100 baked point samples at 24 fps. This is a small reproducible
particle-chain simulation, not hand-keyed bending or a runtime dynamics solver.

`make_center_curve_braid.py` regenerates this scene and the simulation. The
381 strands / 24,384 CVs are still generated once from static root seeds and
three rest braid guides. There is no Scatter and no baked output braid.

The final `guideAnimate` node uses **UsdGenDeform, `usdGen:mode="curveWrap"`**.
It binds each incoming point to a rest centerline segment/fraction and carries
its offset through rotation-minimizing frames on the posed polyline. This
preserves braid thickness and works with a straight or planar rest curve,
which cannot determine the existing 3D RBF field. Matching driver CV topology
and open curves are required; multiple drivers require regionMap and guideRegions.
Driver samples are evaluated as a
polyline; 31 simulation CVs provide the sampling resolution in this example.
Explicit axial twist cannot be recovered from a centerline alone, so the wrap
uses minimum twist. Root attachment is maintained by the pinned driver section.
The deformer is CPU-only; the default empty mode still selects RBF.

### Two centers with Ptex regions

The two `two_*_ptex_regions.usda` scenes share one quad scalp and a real
64×64 Ptex face in `maps/two_regions.ptx`. IDs 0 and 1 partition the interior
of that face. The colored scalp texture is only a visual key; binding reads
the Ptex texels. Both scenes contain one description and one driver prim
holding two animated center curves. The centers use mirrored/scaled trajectories
from the reproducible center-curve simulation.

`CurveSource → GuideInterpolate → Width → regionAnimate (UsdGenDeform)`

Both GuideInterpolate and Deform now accept a direct relationship:

```usda
rel usdGen:regionMap = </World/Motion/Groom/Hair/Maps/Regions>
```

GuideInterpolate samples rest roots and restricts interpolation to guides in
the same region. A guide takes the region of its nearest rest strand root.
Set `usdGen:crossover = 0`. Deform uses `usdGen:mode = "curveWrap"` and:

```usda
int[] usdGen:guideRegions = [0, 1]
```

Each entry labels the corresponding driver curve. Every output strand follows
exactly one center according to its rest-root Ptex ID, with no blending between
regions. IDs must be unique across drivers. Missing driver/guide regions fail
explicitly. Categorical maps require `filter = "nearest"`, `blur = 0`, and
nonnegative integer texels in `firstChannel`; scale, offset and clamp are ignored.
These direct region-map operators currently run on the CPU lane.

The small scene has 2 strands / 128 CVs; the dense scene has 762 strands /
48,768 CVs. Rest root binding, growth and width capture once; only the final
deformer updates across the 100 frames. `make_region_braids.py` regenerates
both scenes and calls `build/usdGenBakePtex.exe` to bake the maps. Run it with
OpenUSD Python, Pillow, and the USD/usdGen DLL directories on PATH. The swapped
map is a regression fixture: reversing its texels must reverse driver assignment.

Run `make_motion_examples.py` with the usdGen/OpenUSD Python environment to
regenerate the original four scenes. `make_animated_sphere.py` also regenerates the first
scene alone. `check_animated_sphere.py` is a testusdview script usable with any
of the seven scenes; it captures all 100 frames into `build/traces/<scene>/frames`.

`motion_validation.json` records full playback counts and operator capture reuse.
`make_previews.py` validates the trace logs and builds the adjacent Storm GIFs
from captured frames. `testUsdGenRbfDeform` checks fixed growth,
posed-first loading, locked braid roots, guide/surface composition, and correct
Hydra publication for a groom with its own independent rotation/translation.
It also checks all CVs against their assigned center, isolation when only one
center moves, swapped Ptex assignments, and invalid categorical-map settings.
`testUsdGenCpuCurveSource` checks that animated skin and shared parent motion
reuse rest root capture while edits to rest normals still invalidate it.
