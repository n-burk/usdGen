# C2 — the published tile `basisCurves` contract

**Status: DRAFT (M1 in progress) — binding design; finalized at M1 exit** (ADR §3: "frozen at
end of M1"; ADR §7: C2 freezes with M1). The table below is the entire contract, taken from
`06-imaging.md` §4.1 with the ADR §5.3 core: prim type `basisCurves`; `hairId` uniform **float**;
`purpose`/`visibility`/`materialBindings` authored by hand (post-flattening); `primOrigin`
absolute outside prototypes, relative inside; `__dependencies` one edge per tile;
`velocities`/`accelerations` blocked except in motion profile P1; `displayStyle/refineLevel = 2`
(the no-opinion **fallback** — an upstream `displayStyle` opinion on the Description wins,
unclamped, and the material binding is masked below refineLevel 2 so Low and Medium match an
unbound native `UsdGeomBasisCurves`);
`minScreenSpaceWidths = 1.0`; `extent` recomputed every deforming frame.

Every `tile_NNNN` under `<Description>/__usdGenRender/` carries **exactly this**. Deviating from
it is a contract break, not a bug fix. Tile naming: `tile_%04u`, one prim per tile,
`nTiles = clamp(ceil(nChunks/chunksPerTile), 32, 256)` (ADR §1 S23/S27; §2.3 `usdGen:tileTarget`).
C2 covers tiles only: guides (§4.2), instancers (§4.3) and `material_storm` (§4.4) are separate
contracts, not frozen by C2.

One edge per tile, never per curve |
**The exactness assert is not optional.** A `points` array longer than `Σ curveVertexCounts` is
replaced wholesale by the fallback colour with only a `TF_WARN`; with `curveIndices` it costs
3.46 ms instead of 0.22 ms (MEASURED, `plan/research/G-storm-throughput-and-prim-granularity.md` §1.4).
Padding and array reuse are off the table; the density scrub keeps element counts fixed by parking
culled strands at a degenerate point with zero width, committing the real count on release (S28).
Gate SI-1 asserts the equality on every tile; gate S-7 measures the parked-CV drag against a real
count change. The publisher already hard-asserts it (`usdGenTilePublisher.cpp:141-146`,
`TF_CODING_ERROR`).

**Velocities.** A `velocities` primvar inconsistent with `points` at the same sample time makes
`HdsiVelocityMotionResolvingSceneIndex` silently replace the deformation samples with
`{start, end}` (`pxr/imaging/hdsi/velocityMotionResolvingSceneIndex.cpp:176-190`). usdGen blocks
`velocities`/`accelerations` whenever it owns `points`, and unblocks them only in profile P1
(`usdGen:motion:mode = velocities`, S32).

## Known M1 deltas (recorded, not silent)

1. **Bake primvar name.** Contract: `primvars/<bakePrimvar>` — the authored
   `usdGen:look:bakeTarget` name. M1 publisher: `UsdGenTilePublication` carries the bake colours
   but **not the authored name**, so the colour is published under the fixed name `bakeColor`
   (`usdGenTilePublisher.cpp:184-192`, the "contract gap" comment). The name must be threaded
   through the publication struct before C2 is finalized at M1 exit; until then `bakeColor` is
   the conforming spelling.
2. **`accelerations` in P1.** Publisher blocks `accelerations` unconditionally and gives
   `velocities` real data only when the engine fills it (P1) — P1 motion itself is post-M1
   (roadmap v2), so the contract row is satisfied at M1 scope.
3. **Single-tuple `widths` → `constant`.** The publisher emits `constant` interpolation for the
   one-float-per-tile case; the contract row allows `vertex` **or** `constant`.
4. **`__dependencies` entry name** is `usdGenSurface`; the contract fixes the count (= 1) and the
   three field values, not the entry name.
