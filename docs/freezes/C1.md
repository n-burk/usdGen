# C1 freeze — `usdGen:` property registry (M1)

Contract C1 (plan/design/adr-v1.md §3): *"the `usdGen:` property names and the
prim type names"*, frozen at the end of M1. Normative source:
`plan/02-schema.md` §1–§2 and §6 (ADR §9 R7 — the single property registry).
Authoritative implementation: `libs/usdGenSchema/schema.usda` (the codeless
domain); checked-in generated resources:
`plugin/usdGenSchema/resources/{generatedSchema.usda, plugInfo.json}`.
The executable check is `tests/testUsdGenContracts.cpp` (T1), which compares
the literal lists below against the live `UsdPrimDefinition`/`UsdSchemaRegistry`.

Status: **RE-BASELINED 2026-09-15**, then frozen again at this baseline.
At the user's direction the registry was cut back to the properties the engine
actually reads: every property whose non-default values were rejected or
ignored, and every property no code path consumed, was removed from
`schema.usda` together with the code behind it. The §2 tables below were
regenerated from that schema; §9 lists what went. Before this re-baseline the
document was FROZEN at M1, and it is frozen again now: any further rename /
retyping / default change / token-set change of an entry below is a C1 break
and requires a new contract version, not an in-place edit (02 §8.1/§8.5).

`usdGen:execution:backend` now has a §2 row. It is the most load-bearing
property in the schema and had no freeze entry before this re-baseline.

Dirty-class vocabulary (02 §2.1): **structural** (graph digest term;
recompile), **structural(topology)** (curve/CV/published-prim count;
re-allocate, no digest), **capture** (re-`Capture()` node+downstream),
**value** (per-frame parameter), **toggle** (`usdGen:enabled` on
topology-preserving operators), **publication** (imaging-only re-emit),
*cosmetic* (never routed).

`UsdGenMaskAPI` was deleted outright. It was the only auto-applied API schema,
and the plugin-level `Info/AutoApplyAPISchemas` block that both `gen_schema`
scripts injected is gone with it, so the plugin now auto-applies nothing. The
mask survives as ONE connectable attribute, `float usdGen:mask = 1.0`, declared
on the abstract `UsdGenStyler` and `UsdGenDeformer` (generators have no
upstream curves to leave untouched, so they declare no mask):

| Old | Replacement |
|---|---|
| `usdGen:mask:amount` | `usdGen:mask`, the operator envelope on every lane |
| `usdGen:mask:random`, `usdGen:mask:randomSeed` | `hash($id, $seed)` in a primitive-domain expression |
| `usdGen:mask:ramp:knots`, `:ramp:interpolation`, `:ramp:spline` | a point-domain expression over `$t` |
| `usdGen:mask:source` | nothing; the Width ImageMap path went with it, and no operator declares a map relationship |
| `usdGen:mask:invert`, `:range`, `:rangeMode`, `:combine`, `:rangeMin`, `:rangeMax`, `:effectPosition`, `:falloff`, `:influenceWidth`, `:noise:*`, `:region` | expression arithmetic; all were dead on both lanes |

Consequences recorded here so a reader of §2 does not have to re-derive them:

- Operator order is the composed hierarchy (reverse sibling post-order under
  the Description's `Ops` scope). `usdGen:terminal` never selected anything;
  the compiler derives the terminal from that order and its diagnostics no
  longer name a property.
- There is no per-operator space or read phase, and no per-operator surface
  override: every node uses the Description's `usdGen:surface`.
- There is one kernel per operator type. `usdGen:algorithmVersion` selected
  nothing (only version 0 was ever registered) and any nonzero value aborted
  the whole compile.
- `usdGen:blend` is gone from every lane, including the framework envelope and
  the GPU kernels. The mask is the only envelope. The internal
  `UsdGenWidthBlend` operator (not a schema type) carries its own
  `usdGen:widthBlend:weight` parameter instead.
- `usdGen:enabled` now has real semantics on both lanes: a disabled styler or
  deformer passes its upstream through unchanged; a disabled generator
  (`UsdGenScatter`, `UsdGenGrow`, `UsdGenCurveSource`) publishes an empty
  curve set.
- `UsdGenMapBindingPurpose::LengthSource` and the Grow length ImageMap went
  with `usdGen:length:source`; `MaskSource` and the Width ImageMap went with
  `usdGen:mask:source`, so the enum and `UsdGenMapBindingDesc::purpose` are
  gone and a map binding is now just a path plus its authored relationship.
- `usdGen:mask` is a value-class parameter: editing the literal re-evaluates
  without a recapture. Connecting it is structural, like any other connection.
  A connection may name the expression PRIM or one of its outputs; both
  resolve to `outputs:result`, or to the expression's single `outputs:*`.
- Both lanes evaluate `usdGen:mask`, literal or connected, as a per-element
  envelope on Width, Noise and Length: groom broadcasts, primitive indexes by
  curve, point indexes by CV. Exactly 0 is a bitwise pass-through on both
  lanes. The CPU reference lane gained its evaluator with
  `expressions/cpuEvaluator.{h,cpp}`, which shares the IR interpreter
  (`expressions/irExec.h`) with the CUDA kernel.
