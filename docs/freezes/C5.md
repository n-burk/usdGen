# C5 freeze — glslfx `inputs:` block (M1)

Contract C5 (plan/design/adr-v1.md §4): *"glslfx parameter names (the shipped
file's `inputs:` block, verbatim)"*, frozen at the end of M1.

Per plan/07-look-maps-expressions.md §2.2, C5 covers **exactly** the
`parameters` and `textures` entries of the glslfx configuration block:
20 parameters + 1 texture = the 21 inputs Sdr reports. The `attributes`
and `metadata` blocks are **outside** the contract and differ between the
shipped files by design (variant B `usdGenHairPreviewPrimvar.glslfx` adds
the `hairTangent` vertex attribute; the translucent file changes
`materialTag` to `"translucent"`).

## Shipped files (usdGenShaders/resources/shaders/)

| File | materialTag | attributes | tangent source |
|---|---|---|---|
| `usdGenHairPreview.glslfx` | `defaultMaterialTag` | `hairT`,`hairId`,`st` | **Variant A** (inData.Neye) — M1 DEFAULT (PW-2 / S-8) |
| `usdGenHairPreviewTranslucent.glslfx` | `translucent` | `hairT`,`hairId`,`st` | Variant A |
| `usdGenHairPreviewPrimvar.glslfx` | `defaultMaterialTag` | `hairT`,`hairId`,`hairTangent`,`st` | **Variant B** (hairTangent primvar + derivative fallback) |

## The frozen block (verbatim, identical in all three files)

The fur shading upgrade preserves all 21 input names and defaults. All three
variants additionally request optional `furTauP`, `furTauN`, `furTipTauP`,
and `furTipTauN` float3 primvars (outside C5). The shared implementation is
`usdGenFurScattering.glslfx`; `selfOcclusion` now controls geometry-derived
extinction when those primvars are present. See `docs/storm-fur.md` for the
bake, cache, native instancing, and approximation limits.

## Verification (M1, MEASURED)

- `python3` JSON extraction of the `parameters`+`textures` blocks from all
  three files, then byte-diff: **identical in all three** (run
  `usdGenShaders/test/checkC5.py` — pasted in the M1 report).
- Sdr parse (`Sdr.Registry().GetShaderNodeFromAsset`, sourceType "glslfx")
  on each file: 21 inputs, 1 output, primvars metadata
  `hairId|hairT|st` (A) / `hairId|hairT|hairTangent|st` (B).
- shaderDefs.usda `inputs:*` attributes: same 20 names, same defaults
  (defaults written in USD notation; Sdr reports the glslfx JSON defaults
  for the shader node itself).

Any rename/reorder/addition/removal of an entry above is a C5 break and
requires a new contract version, not an M1 edit.

## Default retune (M1, in place — no C5 break)

C5 freezes the **names**, their order and the parameter/texture split. The
`default` values are tuning, and one retune has happened since the block was
first written, to fix a viewport blow-out: under usdview's camera light plus
its default dome light the strand tips rendered pure white.

| Input | Was | Now | Why |
|---|---|---|---|
| `specular1Gain` | `0.30` | `0.09` | the lobe is a **unit-peak** Gaussian now, so the gain IS the peak reflectance. The normalized Gaussian it replaced carried a `1/(sqrt(2*PI)*w)` factor worth **5.32x** at the old width, so `0.30` produced a ~1.6 highlight — above white on its own, and roughly 3x once the dome light was also evaluated as a direct light |
| `specular1Width` | `0.075` | `0.120` | a soft sheen along the strand instead of a per-pixel speck |
| `specular2Gain` | `0.16` | `0.05` | same unit-peak convention; TRT stays the weaker lobe |
| `specular2Width` | `0.22` | `0.300` | stays wider than the R lobe |

`rootColor` and `tipColor` are **unchanged**: they mirror the C1 schema
defaults `usdGen:look:rootColor` / `:tipColor`, and on a usdGen tile the root
albedo comes from the baked per-curve `displayColor` primvar regardless
(06 §4.1). The `documentation` strings of `rootColor`, `diffuseGain`, both
specular gains and `selfOcclusion` were rewritten to match the new shading;
documentation is part of the frozen block's bytes, so all three files and the
block above were regenerated together.
